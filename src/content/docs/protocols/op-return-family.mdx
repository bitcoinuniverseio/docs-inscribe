## OP-20 and OP_RETURN inscriptions

One workspace, `/op-return`, covers two things the production contract tracks separately:
free-form OP_RETURN inscriptions, and OP-20 tokens.

**OP-20 is the only protocol in Inscribe with all four creation operations**: `deploy`,
`mint`, `inscribe` and `transfer`. The same workspace also registers and transfers **OP
Names**.

| Property | Detail |
| --- | --- |
| Payload limit | 34,000 bytes, well above the 79-byte standard relay reference |
| File path limit | 25,000 bytes |
| Operations | inscribe, deploy, mint, transfer |
| Service fee note | An `op_names` batch pays the flat 1,500 satoshis **once per name**, not once per order |

That service fee behaviour is the exception worth remembering: for most flows the fee is
charged once per order, and for an OP Names batch it is per name.

Workspace: `/op-return`. Released and ungated.

## Drops

Confirmed data artifacts with stable IDs and on-chain proof.

| Property | Detail |
| --- | --- |
| Payload limit | **256 bytes.** Drops are deliberately small |
| Operations | inscribe, transfer |
| The `/drops` workspace | Browse artifacts and review supported transfers; signing requires verified current custody |
| Where creation happens | Through the Inscribe workspace |

**Drop Pacts** provides reference tools and a resumable tutorial. These tools do not grant
transaction signing, custody, or live contract execution authority.

### Search and recovery

The September 6 repair candidate adds the behavior below. It is under validation;
this documentation does not establish a production deployment or a completed Signet journey.

Use **Find** to search the complete confirmed index by Drop number, full Drop ID, mark,
MIME type, or reveal transaction ID. An all-digit mark needs the `mark:` prefix so it is
not interpreted as a Drop number. Search results retain their filtered total and pages,
including transactions containing more than fifty artifacts. **Refresh** keeps the active
search and page; **Browse all Drops** clears the search and returns to page one. Submitted
searches remain in the URL for reload and browser back/forward navigation.

**Checking**, **Unavailable**, **Degraded**, and **Disabled** are different from a successful
search with no results. **Retry artifacts** retries the collection; **Retry verification**
rechecks source readiness. An unavailable source cannot establish that no Drops exist.
Metadata can remain visible while verification is unavailable, but transfers and proof
links require the exact verified network.

Choose the exact chain used by the order and wallet. Signet and Testnet can share address
prefixes; matching prefixes do not prove the same chain. A connected wallet must report
the selected chain before creating or funding a Drops order. Reloading a saved order
retains its recorded network and requires the same chain before continuing.

Only passive images and plain text preview inline. HTML, SVG, and unknown media remain
downloads. A failed preview does not remove the metadata; **Refresh** retries it. **Copy**
copies the full Drop ID, while the owner control copies the current owner address.

Drops verifies its finalized checkpoint and custody evidence against the shared
Universe-operated Bitcoin Core service. An unavailable verifier, stale checkpoint, or
disagreement with the recorded chain evidence leaves readiness unavailable. There is no
fallback to a public blockchain provider. This verification description does not establish
Signet marketplace availability.

Workspace: `/drops`. Released, and a deployment must switch it on.

## OP_DROP

Deploy, mint and transfer, where every operation is a compact JSON inscription and funding
is **wallet-only**.

OP_DROP appears repeatedly in the asset-safety screening, because several of its flows
choose funding outputs on your behalf: order funding, settlement fee inputs, and ownership
receipt inputs all pass through the classification described in
[asset safety](/docs-inscribe/concepts/asset-safety/).

Its service fee is quoted as its own total rather than as the flat amount.

Workspace: `/op-drop`. Released, and a deployment must switch it on.
