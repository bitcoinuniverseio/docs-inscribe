## Runes

The main protocol here. Etch a new rune, mint an open one, or split a balance across
outputs.

An etch fixes the name, divisibility, premine and mint terms permanently. Read
[etch a rune](/docs-inscribe/create/etch-a-rune/) before you do one.

Runes rounds fee rates to whole satoshis under some conditions, which is one reason the
Normal and Fast tiers can show the same number. That is expected, not a fault.

Workspace: `/runes`. Released and ungated.

## Mezcal

The same three operations, etch, mint and transfer, written differently: **Mezcal writes
JSON records into OP_RETURN outputs instead of runestones**, and it runs on its own index.

Two practical consequences:

- A name on Mezcal and the same name on Runes are different assets.
- **Mezcal quotes its own service fee** rather than the flat 1,500 satoshis. The
  confirmation screen shows the amount that applies.

Workspace: `/mezcal`. Etch, Mint and Transfer are offered. An audit found issues in
discovery, validation, transfer safety and completion reporting. A local repair
candidate dated **6 September 2026** addresses these paths; it has not been deployed
or verified through a funded network journey. The guidance below describes that
candidate and does not certify the running service.

### Etch values

- **Decimals:** a whole number from 0 to 18; leaving it empty uses 8.
- **Symbol:** one Unicode character, such as `M`. A joined emoji or a sequence of
  characters is not one protocol symbol.
- **Mint cap:** the number of public mint transactions, not the number of tokens.
- **Amount per mint** and **reserve allocation:** whole atomic units. With 8
  decimals, 100,000,000 atomic units represent one token.
- **Unlimited:** removes the mint cap while retaining the amount per mint and any
  block limits. A capped supply preview includes the reserve allocation.

Before payment, review the actual order total, network and receiver. A priced mint
also lists its price recipients. Any amount added to meet Bitcoin output dust is
included in the order total.

### Reads, transfer status and recovery

Discovery and balances show an inline error with a retry action when their data
cannot be verified. Previous results can remain visible with their last check time;
they are not a fresh balance or mint eligibility check. Partial wallet reads identify
that some addresses were unavailable.

Transfer amounts retain their exact decimals. Excess fractional digits are rejected
before signing. Signing uses the address that holds the selected balance.

**Submitted** means the transaction was sent. **Confirmed** means Bitcoin has
confirmed it. **Indexed and delivered** requires Mezcal to recognize the intended
transfer. An immediate balance refresh or a transaction id does not prove delivery.

Save an encrypted recovery kit while the transfer is open. After a reload, select
the reference under **Saved transfers** in the Transfer tab and restore its kit.
The browser saves order references; access credentials remain in memory. Pending
signatures can be resumed, and an uncertain submission can retry the saved
transaction. A lost response during initial order creation still needs recovery
before a reload; automatic restoration of an unknown order id is not established.

The supported candidate profile is Bitcoin mainnet. A supported, isolated Signet
profile and real network acceptance have not been established.

## Alkanes

**Mint only.** The registry records a `mint` operation for Alkanes and nothing else, so
Inscribe cannot etch or transfer one for you.

What the workspace does well is show you what is being contested: it ranks Alkane tokens by
live mempool minting, so you can see demand as it happens, and lets you mint by ID.

Workspace: `/alkanes`. Released.

## Runes (Native)

The registry carries a separate **Runes (Native)** protocol with no inscribe surface at
all. It appears in the main and wallet surfaces of Bitcoin Universe, and there is no way to
create one in Inscribe.
